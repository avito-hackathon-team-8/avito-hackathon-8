# Коробыш — frontend

Frontend игрового слоя для Авито. Пользователь развивает виртуального питомца: выполняет ежедневные задания, получает листья, повышает уровень, забирает награды и открывает сундуки.

## Запуск

Для локального запуска нужны Node.js 24+, npm и работающий backend на `http://localhost:8090`.

```bash
cd frontend
npm i
npm run dev
```

Приложение откроется на `http://localhost:5173`. Vite проксирует HTTP- и WebSocket-запросы с `/api` на backend.

При необходимости адрес API можно переопределить:

```dotenv
VITE_API_BASE_URL=http://localhost:8090
VITE_API_BASE_PATH=/api
```

Запуск всего проекта из корня репозитория:

```bash
cp .env.example .env
make up
```

После запуска Docker-окружения frontend доступен на `http://localhost:3000`.
Адрес `http://localhost:5173` используется при локальном запуске через
`npm run dev`.

Основные команды:

```bash
npm run build        # production-сборка
npm run lint         # проверка TypeScript/React
npm run lint:styles  # проверка SCSS
npm run preview      # просмотр production-сборки
```

## Структура

Проект организован по принципам Feature-Sliced Design:

```text
src/
  app/       # провайдеры, роутинг, layouts и глобальные стили
  pages/     # страницы приложения и страница 404
  widgets/   # крупные самостоятельные блоки страниц
  features/  # действия пользователя: вход, имя питомца, открытие сундука
  entities/  # бизнес-сущности: профиль, задания, награды, лидерборд
  shared/    # API-клиент, конфигурация, утилиты, UI-kit, иконки и ресурсы
```

Между слоями используются публичные API через `index.ts`. Внутри одного слайса применяются относительные импорты.

## WebSocket

После авторизации JWT хранится в `sessionStorage` и передаётся в WebSocket через query-параметр `token`.

- `/api/v1/pet/ws` принимает событие `PET_PROGRESS_UPDATED` и сразу обновляет профиль питомца в кеше. При повышении уровня дополнительно ревалидируются уровни и ежедневные задания.
- `/api/v1/daily-report/ws` принимает событие `DAILY_REPORT_UPDATED` и заменяет ежедневную сводку в кеше актуальными данными.

Для соединения профиля настроено автоматическое переподключение с увеличением задержки от 1 до 10 секунд. Соединения закрываются при размонтировании соответствующих компонентов.

## Кеширование и ревалидация

Серверные данные хранятся в кеше TanStack Query. Общие значения `staleTime` и `gcTime` равны 30 секундам.

- WebSocket-обновления записываются напрямую через `setQueryData`, поэтому интерфейс обновляется без дополнительного HTTP-запроса.
- Получение награды за задание или уровень выполняется оптимистично: кеш меняется сразу, при ошибке восстанавливаются предыдущие данные, после успеха запрос ревалидируется.
- После открытия сундука ревалидируется только список наград. Баланс листьев приходит через WebSocket профиля.
- При повышении уровня ревалидируются список уровней и ежедневные задания.
- После авторизации инвалидируется основной кеш приложения, чтобы загрузить данные нового пользователя.

## Особенности реализации

- JWT-авторизация по одноразовому коду и защищённые маршруты;
- адаптивный интерфейс с общими UI-компонентами и типографикой;
- состояния загрузки, ошибок и пустых списков;
- модальные окна для имени питомца и полученной награды;
- анимация питомца в зависимости от уровня и индикатор доступной награды;
- автоматическое восстановление части WebSocket-соединений;
- предварительная загрузка основных изображений приложения.
