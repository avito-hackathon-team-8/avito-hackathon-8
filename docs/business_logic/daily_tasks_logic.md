# Система дневных задач

## Назначение

Система дневных задач предназначена для ежедневного вовлечения пользователя в активность внутри приложения. Выполняя простые и понятные действия, пользователь зарабатывает листья, которые необходимы для развития питомца и участия в лидерборде. Задачи обновляются каждый день, что создаёт ритуал ежедневного посещения приложения и поддерживает интерес пользователя на постоянной основе.

---

## Общие принципы

- Пользователь может выполнять ежедневные задачи для получения листьев.
- Задачи привязаны к календарному дню UTC и создаются бэкендом для текущего дня при первом обращении.
- Доступность задач зависит от уровня питомца:
  - С 1 уровня доступны первые две задачи.
  - С 5 уровня открывается третья задача.
  - С 10 уровня открывается четвёртая задача.
- После выполнения условия пользователь отдельно забирает награду за конкретную задачу.
- За получение награды предусмотрено следующее количество листьев:
  - Задачи 1 и 2: по 45 листьев каждая.
  - Задача 3: 50 листьев.
  - Задача 4: 60 листьев.
- Награду за каждую задачу можно получить только один раз в течение дня.
- После выполнения всех доступных задач пользователь не может выполнить их повторно до следующего обновления.
- На главной странице отображается количество выполненных задач (например, «Выполнено: 2/4»).
- В разделе «Задания» пользователь видит полный список задач текущего дня, включая заблокированные, их условия и прогресс выполнения.

### Статусы задания

| Статус | Значение |
|--------|----------|
| `LOCKED` | Задание пока недоступно из-за уровня питомца. |
| `IN_PROGRESS` | Условие задания ещё не выполнено. |
| `COMPLETED` | Условие выполнено, награду можно забрать. |
| `CLAIMED` | Награда уже получена. |

В счётчике вида «2/4» выполненными считаются задания в статусах `COMPLETED` и `CLAIMED`.
Знаменатель всегда равен четырём и включает задания, заблокированные по уровню.

## Типы задач

Поле `type` принимает один из следующих типов:

| Код API | Название | Что засчитывается в прогресс |
|---------|----------|------------------------------|
| `OPEN_NOTIFICATIONS` | Открыть уведомления | Подтверждённые открытия уведомлений увеличивают `currentCount` на переданный `count`. |
| `ADD_TO_FAVORITES` | Добавить в избранное | Добавления объявлений в избранное увеличивают `currentCount` на переданный `count`. Удаление объявления из избранного не уменьшает уже полученный прогресс. |
| `PUBLISH_LISTING` | Опубликовать объявление | Успешно опубликованные объявления увеличивают `currentCount` на переданный `count`. Черновик не учитывается. |
| `BOOST_LISTING` | Поднять объявление | Успешные применения услуги поднятия к объявлению пользователя увеличивают `currentCount` на переданный `count`. |
| `LEAVE_REVIEW` | Оставить отзыв | Успешно опубликованные отзывы о сделке или пользователе увеличивают `currentCount` на переданный `count`. Черновик отзыва не учитывается. |
| `COMPLETE_DEAL` | Завершить сделку | Завершённые покупки или продажи увеличивают `currentCount` на переданный `count`. Созданная, отменённая или незавершённая сделка не учитывается. |
| `ORDER_WITH_DELIVERY` | Заказать с доставкой | Успешно оформленные заказы с Авито Доставкой увеличивают `currentCount` на переданный `count`. Заказ без доставки не учитывается. |

Для всех типов действуют общие правила:

- Требуемое количество действий приходит в `targetCount`; тип задачи сам по себе его не задаёт.
- Клиент или вызывающий сервис передаёт в API уже подтверждённые агрегированные события.
- `currentCount` не превышает `targetCount`. После достижения цели статус меняется на `COMPLETED`.
- Если `count` отсутствует или меньше 1, сервер считает его равным 1.
- Действия, выполненные до начала текущего дня или пока задача имеет статус `LOCKED`, в дневной прогресс не входят.
- Если в batch-запросе есть событие для недоступной или отсутствующей задачи текущего дня, весь запрос отклоняется.

## Логика обновления задач

1. Новый день определяется по календарной дате UTC.
2. Для каждого дня создаётся фиксированный набор из четырёх задач.
3. Создание выполняется лениво: при первом обращении к списку, прогрессу, записи события или получению награды.
4. Прогресс хранится отдельно для каждого пользователя и каждой задачи текущего дня.
5. При смене даты UTC пользователь начинает новый дневной прогресс.

## API текущей реализации

- `GET /api/v1/tasks?level=...` возвращает четыре задачи текущего дня в порядке слотов. Если `level` отсутствует, некорректен или меньше 1, используется уровень 1.
- `GET /api/v1/tasks/progress?level=...` возвращает `completedCount` и `totalCount`.
- `POST /api/v1/tasks/record` принимает тело `{"level": 5, "events": [{"type": "ADD_TO_FAVORITES", "count": 2}]}` и при успехе возвращает `204 No Content`. Если `events` отсутствует, равен `null` или пуст, сервер возвращает `204` без изменения прогресса.
- `POST /api/v1/tasks/{taskId}/claim` принимает тело `{"level": 5}` и возвращает `taskId`, `rewardLeaves` и статус `CLAIMED`.

| 1 | Открыть уведомления | Открыть 5 уведомлений | 45 листьев |
| 1 | Добавить в избранное | Добавить 3 объявления в избранное | 45 листьев |
| 5 | Опубликовать объявление | Опубликовать объявление | 50 листьев |
| 10 | Завершить сделку | Совершить покупку или продажу | 60 листьев |
